# Evaluation

Accuracy is a measurement, not an opinion. This document describes how the
platform measures transcription quality against reference data, what is
recorded for every run, and — explicitly — what the numbers do **not** mean.

Phase: **6** (evaluation, MLflow, reference datasets, WER/CER, comparison).

## 1. What a measurement is made of

| Piece | Where it lives | Notes |
| --- | --- | --- |
| Reference dataset | `backend/src/stt_platform/evaluation/datasets/stt-eval-core.json` | Versioned manifest: stable clip ids, reference text, language/domain/accent/noise metadata, reference boundaries, provenance |
| Corpus audio | `models/eval-corpus/` (gitignored, I: drive) | Never committed (ADR-007); regenerated by `scripts/make_eval_corpus.py` |
| Accuracy metrics | `evaluation/metrics.py` | WER/CER with a recorded normalization pipeline, cross-checked against `jiwer` |
| Timestamp metrics | `evaluation/timestamps.py` | Availability, boundary error, coverage, monotonicity, degenerate spans |
| Runner | `evaluation/runner.py` | Dataset × provider → per-clip records + aggregates; failures are data, not crashes |
| Platform path | `evaluation/platform.py` | Transcribes through the real job pipeline so latency numbers are the platform's own |
| Tracking | `evaluation/mlflow_logging.py` | Best-effort MLflow runs; the local record stays authoritative |
| Records | `evaluations` + `evaluation_clips` tables; full result as an artifact | PostgreSQL keeps the numbers, object storage keeps the transcripts |

## 2. Reference data and provenance

The manifest marks every clip with a `reference_source`:

| Source | Meaning | Scored? |
| --- | --- | --- |
| `synthetic-tts` | Audio synthesized from known text (Windows SAPI voices, 16 kHz mono) — ground truth by construction | yes |
| `human` | Transcript verified by a human listener | yes |
| `pending-human-verification` | Audio exists, reference text is **not** verified | **no** |

A clip whose reference is unverified is never scored, and its reference text
may be `null`. This is the rule that keeps the numbers honest: the owner's
real-speech sample ships as `pending-human-verification`, so it is excluded
until a human confirms the transcript.

The generator (`scripts/make_eval_corpus.py`) synthesizes each clip, mixes
the declared noise condition with ffmpeg, and writes the **measured**
duration, sha256, and reference boundaries back into the manifest. The
runner additionally hashes the exact bytes it scored, so a result names the
audio it saw.

## 3. Normalization (recorded, versioned)

`NormRules` (`stt-normalize-v1`) is applied to both reference and hypothesis
before scoring, and the rules travel with every result:

1. Unicode NFKC (ligatures, compatibility forms)
2. case fold
3. punctuation → space (keep apostrophes inside words: `don't` stays one token)
4. collapse whitespace, strip

**Digits are not expanded.** Whisper writes "342 dollars" where the reference
says "three hundred and forty two dollars" — that is a *substitution* under
this pipeline, and the `numbers` domain in the shipped corpus shows it
(WER 0.69 on that clip). The alternative — inventing a number normalizer —
would hide a real difference between what was said and what was written.
The rules are recorded per evaluation (`normalization` field) precisely so
that a number is never read without knowing which rules produced it.

## 4. Metrics

### Accuracy (per clip, and aggregated)

- `wer` = (substitutions + deletions + insertions) / reference words
- `cer` = the same at character level
- `wer` is `None` when the reference has no words (never 0.0)
- Aggregates: `wer_micro` (total errors / total reference words — the number
  to quote for a corpus) and `wer_macro` (mean of per-clip WER — dominated by
  short clips). Both are recorded so nobody has to guess which was used.
- Breakdowns by `language`, `domain`, `accent`, `noise` (`by_group`).

### Timestamps

- `segment_availability`, `word_availability` — fraction of units carrying a
  usable span; `None` when the unit type does not exist (e.g. no words at all)
- `boundary_error_s`, `max_boundary_error_s` — mean/max |Δ| at matched
  reference boundaries, `None` when the reference has no boundaries
- `coverage` — fraction of the reference span covered by hypothesis segments
- `monotonicity_violations`, `degenerate_spans` — overlapping/negative spans
  and "one span covering everything" (nominal timings)

Reference boundaries for the shipped corpus are the clip spans (0 → measured
duration), so boundary error includes leading/trailing silence. This is
stated rather than corrected: the reference is coarse, and the metric says so.

### Operational (from the real job records)

`queue_wait_s`, `processing_s`, `end_to_end_s`, `real_time_factor`,
`attempts`, `retries` — measured on the platform's own path, per clip, plus
`failure_rate`. These are the same numbers Phase 5 observes in production, so
an evaluation and a dashboard cannot disagree.

### Cost

Not implemented, deliberately. There is no reliable, machine-readable price
source in this repository, and an invented cost per audio minute would be
worse than an absent one. The inputs (audio duration per clip, provider,
model) are all recorded, so a cost model can be added without re-running
anything.

## 5. Insufficient evidence

A comparison of providers over one recording is not a ranking. Any
evaluation with fewer than two scored clips is flagged
`insufficient_evidence: true`, carried through the API, the frontend, and the
MLflow tags. The flag exists so a single-clip result cannot be quoted as a
quality claim.

## 6. MLflow

- Started with the upstream compose file (see §8). One run per (dataset
  version, provider, configuration) in experiment `stt-evaluation`.
- Params: dataset id/version, provider, model, clips, normalization name,
  decoding (JSON). Metrics: everything numeric above. Tags: dataset,
  provider, model, normalization, `insufficient_evidence`, start/finish.
- The full result JSON is uploaded as the run artifact (`result.json`).
- **Best-effort by contract**: `STT_MLFLOW_ENABLED=false` disables it, and a
  tracking server that is down produces `mlflow: {"status": "error", ...}` in
  the local record instead of failing the evaluation. Requests are
  time-bounded (`STT_MLFLOW_TIMEOUT_S`, default 10 s) so a hung server cannot
  hang a request.
- Artifacts are served through the tracking server
  (`/get-artifact?path=result.json&run_uuid=<run>`); the Python client's
  chunked `download_artifacts()` retries against the server-proxied store and
  is slow in this compose setup — read artifacts via the endpoint or the UI.

## 7. API

| Method | Path | Notes |
| --- | --- | --- |
| `POST` | `/v1/evaluations` | Runs synchronously (bounded by `STT_EVALUATION_MAX_CLIPS`, default 25) → `201` + the full record |
| `GET` | `/v1/evaluations` | Comparison rows (one per evaluation) |
| `GET` | `/v1/evaluations/{evaluation_id}` | Full record with per-clip metrics |

Errors are structured and actionable: `DATASET_NOT_FOUND` (404),
`DATASET_NOT_READY` (409, tells you to run the corpus generator),
`EVALUATION_TOO_LARGE` (422, names the limit and the setting),
`EVALUATION_NOT_FOUND` (404), `PROVIDER_NOT_FOUND` (422).

A run is synchronous on purpose: the shipped corpus is ~1 minute of audio at
RTF ≈ 0.07. A corpus that needs minutes belongs in a workflow, and the cap
says so instead of hanging the request.

## 8. Running it

```bash
# 1. MLflow tracking server (upstream compose, sparse checkout)
cd /i/voice-agent-course
git clone --depth 1 --filter=blob:none --sparse https://github.com/mlflow/mlflow.git
cd mlflow && git sparse-checkout set docker-compose && cd docker-compose
cp .env.dev.example .env
docker compose up -d          # UI + API on http://localhost:5000
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:5000/health   # 200

# 2. Reference corpus (audio is never committed)
cd /i/voice-agent-course/local-stt
cd backend && uv run python ../scripts/make_eval_corpus.py

# 3. An evaluation, through the API
curl -s -X POST http://127.0.0.1:8078/v1/evaluations \
  -H 'Content-Type: application/json' \
  -d '{"dataset_id": "stt-eval-core", "language": "en"}' | head -40
```

Settings: `STT_EVALUATION_DATASETS_DIR`, `STT_EVALUATION_AUDIO_ROOT`,
`STT_EVALUATION_MAX_CLIPS`, `STT_MLFLOW_ENABLED`, `STT_MLFLOW_TRACKING_URI`,
`STT_MLFLOW_EXPERIMENT`, `STT_MLFLOW_TIMEOUT_S`.

## 10. Known limits

- The shipped corpus is **English only** (the machine's SAPI voices are
  English) and synthetic; real-speech clips stay unscored until a human
  verifies their transcripts.
- Reference boundaries are clip-level, not word-level, so boundary error is a
  coarse signal.
- `jiwer` is a dev-only dependency used to cross-check WER/CER in tests; the
  runtime implementation is ours and is what produced every recorded number.
- Cost per audio minute is not computed (§4).
- MLflow is optional: with it disabled, comparisons live only in PostgreSQL
  and the API.
