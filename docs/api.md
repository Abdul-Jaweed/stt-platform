# API walkthrough (`/v1`)

Base URL locally: `http://127.0.0.1:8200`. Interactive schema: `/docs`
and `/openapi.json` (OpenAPI 3.1, generated by FastAPI).

## Endpoints

| Method | Path | Purpose | Success | Errors |
|---|---|---|---|---|
| POST | `/v1/transcriptions` | create a job — multipart `file` **or** form `object_key` (exactly one), optional form `provider` / `language`, optional header `Idempotency-Key` | **201** sync (terminal job) or **202** async (`QUEUED`) `JobRecord` + `Location` | 413 `UPLOAD_TOO_LARGE`, 415 `UNSUPPORTED_MEDIA`, 422 `AUDIO_TOO_LONG` / `PROVIDER_NOT_FOUND` / `VALIDATION_ERROR` / `INVALID_OBJECT_KEY`, 503 `STORAGE_NOT_CONFIGURED` |
| POST | `/v1/transcriptions/uploads/presign` | get a one-shot PUT URL for a large original (JSON `{"filename": "x.wav"}`) | 200 `{object_key, upload_url, method, expires_in_s}` | 503 `STORAGE_NOT_CONFIGURED` |
| POST | `/v1/transcriptions/preview` | live preview of the audio captured so far: multipart `file`, optional form `provider` / `language`. No job, no storage, nothing persisted | 200 `LivePreviewResponse` (`is_final: false`) | 415 `UNSUPPORTED_MEDIA`, 422 `LIVE_PREVIEW_LOCAL_ONLY` (managed provider) / `AUDIO_TOO_LONG` (past `STT_MAX_LIVE_PREVIEW_DURATION_S`, default 120 s) / `VALIDATION_ERROR`, 413 `UPLOAD_TOO_LARGE` |

| GET | `/v1/transcriptions/{id}/result` | canonical transcript | 200 `TranscriptResult` | 404 `JOB_NOT_FOUND`, 409 `JOB_NOT_READY` |

## OpenAPI

The application is the specification: `GET /openapi.json` serves it
interactively at `/docs` (Swagger UI) and `/redoc`, and the same document is
committed as [`docs/openapi.json`](openapi.json). It is generated by

```bash
cd backend && uv run python ../scripts/export_openapi.py
```

and three tests keep it honest: the pinned HTTP surface must equal the
mounted routes, the schema must equal that surface in both directions, and
the committed file must not drift from the application
(`tests/integration/test_openapi.py`). The streaming WebSocket cannot appear
in OpenAPI by construction — it is pinned against the route table and this
document instead.

Behind the console's nginx the API keeps its own origin, so the interactive
docs live at `http://127.0.0.1:8200/docs` (and at `http://127.0.0.1:8080/`
the console serves its own UI, not the API's docs).

## Live preview (while recording)

```bash
# the audio captured so far, sent every few seconds by the browser
curl -s -X POST http://127.0.0.1:8200/v1/transcriptions/preview   -F file=@take-so-far.webm -F language=en
# → {"text":"Hello, I'm ...","segments":[…],"provider":"faster-whisper",
#    "model":"large-v3-turbo","audio_duration_s":7.4,"is_final":false}
```

Three properties are contractual, not incidental:

1. **Local provider only.** A managed provider answers `422
   LIVE_PREVIEW_LOCAL_ONLY`. The preview fires every few seconds; routing that
   to a paid API would spend quota on the caller's behalf.
2. **Nothing is persisted.** No `jobs` row, no object in storage, no
   evaluation; the uploaded bytes are deleted before the response is returned.
3. **It is not the transcript.** `is_final` is always `false` and there is no
   `job_id` — the finished artifact still comes from
   `GET /v1/transcriptions/{id}/result`.

The text is produced by re-transcribing the whole take each tick, which is why
it grows monotonically instead of showing seams; `STT_MAX_LIVE_PREVIEW_DURATION_S`
bounds what that costs.

## Streaming (while audio is spoken)

`WS /v1/transcriptions/stream` is the console's live path: partials while an
utterance is open, a final when the VAD closes it, session-absolute timestamps,
and a `done` whose `text` is the authoritative concatenation. It runs on the
**local** model only (a managed provider is refused before any audio is
accepted), writes nothing to the database or storage, and is bounded by
`STT_STREAM_MAX_DURATION_S` / `STT_STREAM_IDLE_TIMEOUT_S` /
`STT_STREAM_MAX_SESSIONS` / `STT_STREAM_MAX_FRAME_BYTES`.

```bash
# python -m websockets ws://127.0.0.1:8200/v1/transcriptions/stream
#   -> {"type":"start","language":"en","input_format":"pcm16"}
#   -> <binary audio frames>          (16 kHz mono s16le, or a container stream)
#   -> {"type":"stop"}
#   <- ready, partial…, final…, done
```

The whole protocol, its error codes and its threading model are in
`docs/streaming.md`; `scripts/e2e_phase8.py` proves a streamed take and the
same take as a job agree.

## Sync vs async routing (server-side, never client-controlled)

With object storage configured:

- audio `≤ STT_MAX_SYNC_DURATION_S` (default 180 s) → **synchronous**
  (201; the job is terminal when POST returns — the Phase 1 contract);
- up to `STT_MAX_ASYNC_DURATION_S` (default 7200 s) → **asynchronous**
  (202; `status=QUEUED`, original preserved in object storage, dispatched
  via the transactional outbox to a Temporal workflow);
- beyond that → 422 `AUDIO_TOO_LONG`.

Without object storage the service is sync-only (Phase 1 behaviour).

## Presigned uploads (large files skip the multipart hop)

```bash
# 1. get a slot (opaque, scope-bound key + SigV4 PUT URL)
curl -s -X POST http://127.0.0.1:8200/v1/transcriptions/uploads/presign \
     -H 'Content-Type: application/json' -d '{"filename":"talk.wav"}'
# → {"object_key":"audio/local/<uuid>/original.wav","upload_url":"http://127.0.0.1:29000/…","method":"PUT","expires_in_s":900}

# 2. PUT the bytes straight to storage
curl -s -X PUT --upload-file talk.wav "$UPLOAD_URL"

# 3. create the job by key (no file part)
curl -s -X POST http://127.0.0.1:8200/v1/transcriptions \
     -F "object_key=audio/local/<uuid>/original.wav"
# → 202 {"status":"QUEUED",…}
```

The server validates the echoed key against the caller's scope
(`INVALID_OBJECT_KEY` otherwise); the worker re-validates the stored
bytes before transcribing. Presigned URLs are **SigV4** — the boto3
default (SigV2) signs `Content-Type` into the URL and rejects clients
that send one.

## Error shape

Every error body:

```json
{"error": {"code": "UNSUPPORTED_MEDIA", "message": "ffprobe rejected the file: ..."}}
```

Pinned mapping: validation → 415/413/422, missing job → 404, not-ready /
conflict / illegal transition → 409, provider failure → 502, missing
storage for an async-only request → 503 `STORAGE_NOT_CONFIGURED`,
anything unexpected → 500 `INTERNAL_ERROR` (message deliberately opaque).

## Idempotent clients

Send `Idempotency-Key: <opaque>` on POST (both paths):

- replay with the **same audio bytes/object key and parameters** returns
  the same job (same `id`, no re-processing);
- replay of the same key with **different** parameters → 409
  `IDEMPOTENCY_CONFLICT`.

The fingerprint is `sha256` over `(provider, language, options,
object_key)` + audio bytes — file names never matter. See
`docs/reliability.md` for the exact semantics and known gaps.

## Verified real runs

### Phase 1 (2026-10-11, synchronous path, large-v3-turbo on CUDA)

```bash
curl -s -F "file=@audio/sample.wav" -F "language=en" \
     -H "Idempotency-Key: e2e-demo-1" \
     http://127.0.0.1:8200/v1/transcriptions
```

- → **201 Created** in 3 s wall; job `SUCCEEDED`,
  `actual_provider=faster-whisper`, `model=large-v3-turbo`
- audio metadata (probed, extension never trusted):
  `wav / pcm_s16le / 16000 Hz / mono / 10.0 s / 320044 B`
- result: `"Hello, I'm Abdul Javid, AI Engineer at …"`, `language: "en"`,
  `timestamp_granularity: "word"`, 26 words, **RTF ≈ 0.078**

### Phase 2 (asynchronous path, real worker + Temporal + RustFS)

Driven by `scripts/e2e_phase2.py` against the live compose stack
(200 s wav built from `audio/sample.wav`; raw evidence in
`results/phase2_e2e/result.json`):

- **job A** multipart → **202** `QUEUED` → worker transcribes from
  object storage → `SUCCEEDED` in 18.1 s wall; **RTF ≈ 0.059**
  (≈ 17× realtime), 44 segments / 287 words, word-level; trail
  `ACCEPTED→VALIDATING→STORED→QUEUED→PROCESSING→SUCCEEDED`
- **job B** presigned PUT (with `Content-Type: audio/wav`) → create by
  `object_key` → **202** → `SUCCEEDED` (342 words)
- **job C** cancel while queued → **200** → `CANCELLED` (trail ends
  `QUEUED→CANCELLED`)
- **job D** worker killed → job stayed `QUEUED` (six polls over ~12 s) →
  worker restarted → `SUCCEEDED` (durable across worker restarts)

Exact counts, trails and RTF: `results/phase2_e2e/result.json`.
